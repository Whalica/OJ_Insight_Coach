# OJ Insight 教练端完整需求文档

*需求确认版  2026 年 9 月 29 日  ·  仅用于需求分析*

本文面向 OJ Insight 项目负责人，明确独立教练端应用的业务范围、人员与 OJ 数据规则、分期交付和验收依据。教练端以单机本地数据为中心，第一阶段先完成会员档案与多人 OJ 数据的闭环；其他原始候选功能保留并按依赖关系分期。本文不包含开发任务或代码设计。

## 一 项目目标与产品边界

- 教练端是独立桌面应用，首期支持 Windows、macOS、Linux。由一位负责人在一台电脑上操作；管理职务可记录，但首期没有多人登录与权限分配。

- 人员、报名、管理记录、账号配置和同步结果保存在本地。仅获取 OJ 数据时需要联网；不要求 OJI 账号、云数据库、会员在线门户或常驻云服务。

- 个人版 OJI 继续用于制作跨 OJ 题单并导出 JSON，负责人在群内发布。教练端不建设消息推送或按人分配题单。后续可导入同一 JSON 对照多人完成情况。

- 数据完整性优先：仅在役观察会员和正式会员继续同步。数据缺失、凭据缺失、同步失败与可确认的零必须分开显示。

## 二 交付阶段

| 阶段 | 范围与完成标志 |
| --- | --- |
| M1 人员与数据闭环 | 三端本地应用；招新批次与报名表导入；逐人／批量审核；身份与档案；多文件 OJI 配置导入、匹配确认和手动修正；全部现有 OJ 的手动与可关闭自动同步；多人总览、单人 Platforms 详情、AC 打卡；完整备份恢复。 |
| M2 日常管理 | 人工考核和转正记录、奖惩、会员统计；整体、阶段、个人训练计划的起止日期、内容与备注；训练效果回看。 |
| M3 题库与训练深化 | 教练精选题库、原 OJ 标签及难度、外部题解链接、链接与 JSON 导入、分类检索和题目统计；题单多人完成对照；量化计划和目标进度。 |
| M4 活动与队伍 | 居家寒假集训计划、参加人员、每日安排和总结；赛事信息库、个人及队伍报名、费用／缴费状态、名单表格导出、参赛成绩；跨赛事长期队伍。 |

## 三 人员档案与身份规则

### 入会报名与审核

MEM 01  建立招新批次，例如某年秋招或春招；每次申请记录所属批次、提交信息、审核结果和时间。同一学号再次申请沿用人员档案，但保留独立申请历史。

MEM 02  负责人可以手动建档，或从腾讯文档下载固定表头报名表导入。M1 不连接腾讯文档账号，不建设任意表头映射。导入前校验字段并预览新增、重复与错误行；重复学号不得静默覆盖。

MEM 03  入会报名必填：姓名、性别、学号、学院、专业、电话、QQ 号、是否参加新生集训、是否有编程或程序设计基础。选择“有基础”时可选填经历描述。OJ 账号可在入会后补充。

MEM 04  负责人可逐人审核，也可选择多人批量同意或拒绝；批量同意时统一设为观察会员或正式会员。导入报名表本身不触发入会或同步。

MEM 05  通过申请可直接成为观察会员或正式会员。观察会员没有系统强制观察期，转正由负责人依据人工考核决定并记录。退会、除名和再入会均保留变化历史。

### 身份模型与留档

| 维度 | 允许的业务含义 | 用途 |
| --- | --- | --- |
| 申请结果 | 待审核、同意、拒绝 | 记录每次入会申请的结论；历史不可因再次申请被覆盖。 |
| 培养身份 | 观察会员、正式会员 | 表达培养阶段，可由负责人变更并留下时间与备注。 |
| 在会状态 | 在役、退会、除名 | 决定是否继续同步，退出不删除历史。 |
| 管理职务 | 会长、部长、教练等或无 | 仅为档案信息；单人使用的 M1 不据此分配软件权限。 |

报名者、被拒绝者、退会及除名人员仍可被检索和回看；仅“在役且培养身份为观察或正式”的人员进入同步名单。退会或除名时立即停止同步并清除 Cookie／Session，保留账号标识、已同步数据、申请及训练历史；重新入会需重新导入账号配置。

## 四 OJ 账号导入与同步

### 账号导入

DATA 01  会员通过个人版 OJI 的现有导出功能提供文件。教练端支持一次选择多份文件，先展示文件与会员对应表，尝试利用文件内可用账号标识和已有档案提出匹配建议；负责人核对整表后执行。首次导入、冲突或无法可靠匹配时须手动指定会员。

DATA 02  负责人可手动补录或修正 OJ 账号配置。同一人的再次导入整体替换其配置；新文件未提供的 Cookie／Session 清除。预览明确提示凭据变化，不以旧凭据填补新文件的空缺。

DATA 03  个人版 OJI 普通个人信息 JSON 默认不包含 Cookie／Session，只有会员主动完整导出并确认才包含。导入普通文件后若相应平台需要凭据，应标注“缺少凭据”，不能推断该会员没有做题。导入时只使用账号同步所需的信息。

### 同步范围与可靠性

SYNC 01  首期覆盖同期个人版 OJI 已支持的全部 OJ：Codeforces、AtCoder、洛谷、牛客、QOJ、LeetCode；后续平台跟随 OJI 数据能力演进。各平台字段与可用记录不同，教练端不虚构缺失信息。

SYNC 02  支持按需手动同步，以及软件运行期间按可设置间隔自动同步；自动同步可以关闭。两种方式都只处理在役观察／正式会员。网络访问仅用于向 OJ 获取数据。

SYNC 03  每位会员、每个平台呈现最近同步时间、获取结果及数据覆盖边界。同步失败保留历史缓存；区分成功且可确认零、缺少凭据、无可用细粒度数据、网络或站点失败等状态。

SYNC 04  批量处理按会员与平台呈现进度和结果；单项失败不把其他成功项改为失败，也不把失败项显示为未训练。

## 五 多人总览与训练观察

VIEW 01  多人总览默认聚焦在役会员，提供姓名、培养身份、最近可确认 AC 日期、近 7 日和 30 日新通过的不同题目数、需要关注的同步异常；历史人员可另行筛选。总览保持精简，不复制所有平台明细。

VIEW 02  进入单人详情后查看接近个人版 OJI Platforms 页的重要平台统计、逐平台状态和时间信息；可按 OJ 查看平台可提供的难度、Rating、逐题 AC 或汇总数据。

VIEW 03  近 7／30 日新增题数按首次通过的不同题目计算，同题重复 AC 不增加题数。某日若有可确认 AC，即使题目曾经通过，也算当天 OJ 训练打卡；无可靠提交日期时不推断打卡或缺勤。

VIEW 04  入会前基础与入会后增量可在后续分析中区分，但不属于 M1 必须实现的统计。

## 六 考核 奖惩与训练管理

MGT 01  M2 中由负责人填写考核时间、结果、评语及依据，OJ 统计仅供参考。观察会员转正由人工确认；不设置自动及格线、自动转正或自动奖惩规则。

MGT 02  奖惩为档案中的人工事件，包含类型、日期、原因、备注；不设置积分制或等级规则。会员统计可按招新批次、在会状态和可获得的训练数据汇总。

TRAIN 01  M2 支持整体计划、阶段计划和个人规划，早期记录起止时间、内容与备注。M3 再加入可配置的量化目标、目标进度及效果评估。

TRAIN 02  平时打卡由同步到的 OJ AC 自动产生，会员无需使用教练端。负责人通过个人版 OJI 题单 JSON 在群内发布训练题目；教练端不另做通知推送或成员任务分配。

## 七 知识点题库与题单

BANK 01  M3 的题库只收录教练主动挑选的题目，不把所有会员做题记录自动纳入。支持单题链接、批量粘贴链接和 OJI 题单 JSON 导入；不要求在教练端浏览外部 OJ 全站目录再批量选题。

BANK 02  题目主要使用原 OJ 标签，教练可补充标签并保留来源；难度仅保留原 OJ 的数据及来源，未提供时标明缺失，不建立跨 OJ 统一换算。知识点树是未来可选整理能力，不作为题库使用前提。

BANK 03  题解仅记录外部链接及教练备注，不在教练端编辑或托管全文。支持按平台、标签、原站难度、备注等检索，以及题库题目统计。

BANK 04  “训练题目包”沿用个人版 OJI 的题单 JSON。M3 导入同一份 JSON 后，可查看在役会员逐题和整单完成情况；题单发布前已 AC 也算完成，同时区分发布前已通过与发布后新增。无需题单推送、受众分配或训练团队。

## 八 寒假集训

CAMP 01  原始清单中重复的寒假集训章节合并为一项。M4 记录集训计划、参与的在役会员、每日训练安排和集训总结；每日表现关联已有 OJ AC 打卡与统计。

CAMP 02  集训通常居家进行，不另做线下到场考勤，也不建设物资管理。同步数据不完整时不能将当天标为缺勤。

## 九 赛事报名与长期队伍

EVENT 01  M4 建立通用赛事信息库和报名流程，覆盖蓝桥杯、码蹄杯、天梯赛、百度之星及其他高校比赛。赛事记录包含名称、时间、报名截止、地点或线上方式、官方链接及报名费用等。

EVENT 02  报名仅从已入会且在役的观察／正式会员中选人。负责人可手动添加或从比赛报名表导入，不建设会员在线自助报名。支持个人及赛事队伍报名。

EVENT 03  维护个人或队伍的缴费状态，教练端不直接收款。支持将一场比赛的报名名单导出表格；赛后记录实际参赛、成绩和获奖结果，保留当时名单和历史。

TEAM 01  后续支持跨赛事沿用的长期队伍，记录队伍名称、成员加入退出时间、参赛历史。赛事上的实际阵容作为历史快照，不随长期队伍的后续成员变化而改写。

## 十 备份 恢复与数据边界

SAFE 01  M1 可完整备份人员档案、申请与身份历史、OJ 配置、同步结果和管理记录，支持在三种桌面系统之间恢复。恢复是完整数据迁移，不把不同负责人的档案默默合并。

SAFE 02  备份可选择设置密码加密。允许无密码导出，但导出前须明确提示备份可能含电话、QQ 和有效 Cookie／Session。加密备份丢失密码无法恢复。

SAFE 03  凭据只供本地应用访问相应 OJ，不在会员统计界面展示原值；退会、除名或账号重新导入时执行前述清除规则。

## 十一 M1 验收场景

| 场景 | 可观察结果 |
| --- | --- |
| 招新导入 | 导入固定表头报名表，九项必填列缺失时指出原因；学号重复进入核对列表，原档案不被静默覆盖。 |
| 审核与身份 | 同一批次可逐人或批量审核；批准时指定观察或正式。被拒绝者留档且不进入同步。 |
| 批量账号交接 | 多文件导入先给出匹配建议，负责人确认后写入；冲突要求手动指定。再次导入缺少凭据时清除旧凭据。 |
| 同步与异常 | 手动和运行期间自动同步均只处理在役人员；某个平台失败不抹除旧数据，也不显示为零。 |
| 统计与打卡 | 不同题目的首次 AC 进入新增题数；重复 AC 不增加题数，但有可靠日期时可形成打卡。 |
| 退出与恢复 | 退会后停止同步、清除凭据、历史可查；完整备份能在另一桌面系统恢复。 |

## 十二 待细化事项与明确不做的功能

以下事项不阻挡本文的阶段划分，可在对应阶段的交互设计前定稿：自动同步启动时是否立即执行及默认间隔；日期统一采用的时区；汇总报表的导出列；赛事报名表、成绩和奖项的具体字段；知识点树的后续形式。此处不将未讨论的规则写成已确认需求。

首期明确不做会员在线门户、多管理员账号及权限、云同步、题单推送与按人分配、训练团队、自动考核结论、统一难度换算和整站题目目录浏览。寒假集训不单列线下考勤及物资管理；长期队伍留到 M4。
