# OJ Insight Coach

面向程序设计社团与集训教练的本地管理工具。它将会员档案与多 OJ 训练数据放在同一个工作台，帮助负责人完成招新审核、训练观察和历史留档。

> **项目状态：需求分析中。** 本仓库 README 描述目标和分期范围，不代表下述功能已经实现，也不提供安装包或运行指令。

## 为什么做这个项目

个人版 [OJ Insight](https://github.com/Whalica/OJ_Insight) 已能整合单个用户在多个 OJ 的训练数据。教练需要进一步管理多名会员：知道谁仍在会、账号数据是否可用、近期做了哪些新题，并在人员更替后保留完整记录。

OJ Insight Coach 规划为**独立桌面应用**，避免将社团管理功能塞进个人版 OJI。首期由一位负责人在一台电脑上使用，计划支持 Windows、macOS 和 Linux。档案、账号配置、同步结果和管理记录保存在本地；仅向 OJ 获取数据时需要联网，不依赖云服务或会员在线门户。

## 核心工作流程

1. **建档与审核**：按招新批次，从腾讯文档下载固定表头的报名表并导入，也可手动建档。负责人逐人或批量同意、拒绝入会；通过时设为观察会员或正式会员。
2. **关联 OJ 账号**：会员使用个人版 OJI 的现有导出功能提供账号配置。教练端可批量选择多个文件，建议匹配已有档案，由负责人核对后导入；也可手动修正账号。
3. **同步与观察**：仅对在役观察会员和正式会员手动同步，或开启可设置间隔的自动同步。在多人总览查看近期训练和同步状态，进入个人详情查看各平台的重要统计。
4. **保存历史**：退会或除名后停止同步并清除 Cookie／Session，保留人员、账号标识和已获取的历史数据。负责人可备份并迁移完整本地资料。

## 首期范围

| 领域 | 计划能力 |
| --- | --- |
| 会员档案 | 招新批次、固定报名表导入、学号重复核对、逐人及批量审核、观察／正式身份、退会与历史记录 |
| 账号交接 | 多份 OJI 导出文件批量导入、匹配建议与人工确认、手动补录和修正 |
| 多 OJ 数据 | 对接个人版 OJI 同期支持的 Codeforces、AtCoder、洛谷、牛客、QOJ、LeetCode 等平台；手动及可关闭的定时同步 |
| 训练观察 | 多人关键指标总览、接近 OJI Platforms 的个人平台详情、基于可靠 AC 记录的每日打卡 |
| 数据迁移 | 完整备份与跨系统恢复；导出备份时可选择密码加密 |

各 OJ 提供的数据并不一致。教练端会区分**已确认的零、缺少凭据、没有可用明细、同步失败和旧缓存**，不会把取不到的数据当作会员没做题。

近期新做题数按首次通过的不同题目统计；同题重复 AC 不增加题数，但若有可靠日期，仍可计为当天训练打卡。无法取得可靠日期时，不推断打卡或缺勤。

## 后续阶段

| 阶段 | 规划内容 |
| --- | --- |
| 日常管理 | 人工考核和转正记录、奖惩、会员统计；整体、阶段和个人训练计划 |
| 题库与训练深化 | 教练精选题库、原 OJ 标签和难度、题解链接；导入 OJI 题单 JSON 查看在役会员的完成情况；量化目标和进度 |
| 活动与队伍 | 居家寒假集训计划与总结；赛事信息、报名费用和缴费状态、名单导出、成绩与获奖；跨赛事长期队伍 |

训练题单继续由负责人在个人版 OJI 制作，导出 JSON 后在群里发布。教练端不另做消息推送、按人分配题单或会员在线打卡。寒假集训通常居家进行，不单列线下考勤和物资管理。

## 数据与账号边界

- 只有**在役观察会员和正式会员**参与后续 OJ 同步。申请者、被拒绝者、退会及除名人员保留档案，但不在同步名单中。
- OJI 的普通个人信息 JSON 默认不包含 Cookie／Session；只有会员主动选择完整导出并确认后才包含。缺少凭据的平台应提示原因，不推断为零题量。
- 对同一会员再次导入时，以新文件整体更新账号配置；新文件未包含的 Cookie／Session 会被清除，并在导入预览中提示。
- 完整备份可能包含联系方式和有效凭据。可以选择密码加密；无密码导出前须明确提示文件内容。

## 项目边界

首期面向单人本地管理，不建设多管理员权限、云同步或会员在线门户。比赛报名只面向已入会且在役的观察会员和正式会员。题库由教练主动精选，不自动收录所有会员的已做题；难度保留原 OJ 数据，不做统一换算。
